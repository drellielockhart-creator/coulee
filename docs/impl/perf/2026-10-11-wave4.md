## Changes

1. psyche/system.ts: reuse the item API’s synchronous inventory pass across proposals. The existing try/finally clears it, with live deletion checks and creation/movement invalidation.
2. provisions/meals.ts: compute age/physiology/value factors once per daily calorie estimate, preserving multiplication and rounding order.
3. items/api.ts and provisions/environment.ts: keep the sorted stack snapshot in that inventory pass; filter deletions live. Storage and devices avoid repeated numeric-key enumeration.
4. needs/system.ts and needs/api.ts: optional untraced hourly ledger for routine updates/projections. Equations are shared; views retain existing explanations and emitted events are unchanged.
5. psyche/thoughts.ts: skip fallback candidates already covered by an external drive/norm before target scans and text construction. No RNG occurs in the skipped candidate builder.

All caches introduced here live within existing synchronous passes; no cache is added to World or retained across simulations. No content, event shape, RNG or schedule changes.

## Remaining costs and next work

The budget is not met: the final year is 17.10 ms/hour (17.058 in systems), versus 5 ms/hour. At the requested 4× phone multiplier, this is approximately 68 ms/hour. This is an extrapolation, not a phone benchmark. Untouched systems also got faster between the baseline and final year; host contention/GC noise means the full 57% measured improvement should not be attributed solely to the edited functions.

The 90-day CPU profile after optimization 3 (`step3.cpuprofile`, ranked with `rank-profile.mjs`) attributes roughly 37% of sampled time to `planReadiness`, 13% to `serveMeal` (overlapping with the planner), 7% to thought-rule candidates, 6.5% to `requiresFail`, and 2.9% to `memoryDigests`. Remaining self-time leaders include planner/meal callbacks, `idsOf`, `stacksDeep`, memory digests and GC. These percentages are inclusive where a function is named, and must not be added.

Concrete next ideas:
- Readiness: pass actor/household membership and hearth lookup tables through its private projection; avoid repeatedly scanning even its reduced world. Clone only mutable nutrition/pending-meal fields instead of JSON round trips, with a projection-isolation test. Retain hourly storage, water, nutrition and prep stepping exactly.
- Social/psyche: cache age and structural preconditions within each existing Pair evaluation, and index only requested memory targets when forming proposal digests. Invalidation must cover memory salience, new memories, relationships and defenses; do not persist a cache across independent sims.
- Foundation request: `packages/core/src/time.ts:yearsBetween` currently computes full calendars (including moon/daylight) twice just to compare dates. Use the existing civil-date arithmetic only, preserving pre-epoch birthdays and leap dates. This foundation-owned change was not made.
- Generated CLI overhead is 2.84–2.89 ms/hour amortized over 90 days, outside system timers. Profile generation separately before treating that portion as phone tick cost.
- Behavior-changing options, NOT implemented: shorter or approximate readiness projections; less frequent household ration decisions; less frequent psyche arbitration; smaller candidate/memory caps. Each can change ration thresholds, decisions, event counts or RNG use and requires a separate design decision.
