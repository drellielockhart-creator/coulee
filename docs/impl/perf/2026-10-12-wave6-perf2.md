## Optimizations

1. **Civil-date age checks.** `yearsBetween` uses the same civil-date conversion without calculating unused lunar phases, daylight, season, and formatting fields. Birthday and leap-day behavior is unchanged.
2. **Stationary readiness projection work.** Membership, holder locations, and scheduled daily calorie estimates are memoized only inside each private projection, with `finally` cleanup. The projection never moves, adds, kills, or changes the energy traits of its eaters. Inventory remains live. Nutrition records and fires use explicit copies instead of JSON round trips; both intake arrays are copied. Holder-stack collection avoids intermediate `flatMap`/`map` arrays, and the daily calorie loop reuses a private hourly calendar object.
3. **Listener retention index.** A bounded `Map` keyed by the actual talk record stores its count and a conservative next-expiry bound. It clears at 512 distinct records; eviction only triggers recomputation. Remembering a line scans the record only when expiry or the 1024-entry cap requires it. Daily pruning refreshes the index. Record replacement/save reload reconstructs it; no cache enters World. Refresh order, expiry boundaries, timestamp ordering, and numeric tie breaks remain unchanged.
4. **Discarded explanations.** Meal-score arithmetic retains the exact term rounding and summation order, while private projections avoid allocating the named term objects. Live meal explanations preserve their labels and order. Daily nutrition-condition terms are constructed only when the condition changes.
5. **Inventory index lifetime.** Leaf deletion keeps the existing index; every consumer checks deletion against the live table. Removing a container finds its immediate children through the index and invalidates it when hoisting changes their locations. Nested inventory passes share the active index and leave cleanup to the outer call. Social now uses the same mutation-aware inventory pass as psyche and provisions.

No horizon, hourly kernel, ration threshold, actor choice, RNG key/draw, or candidate-selection policy was changed. Sibling tactical, web, and charm-theft implementation files were not edited.

Behavior-preserving candidates for a later pass:

- Compile preparation paths and active observance lists within a content/read-only pass. Recipe recursion, schedule selection, and repeated arrays remain visible costs.
- Reuse whole household readiness results only with an exact dependency key. It must cover inventory quantities/partials/spoilage/opening and placement, water, fires, nutrition history, schedule/date/age/weather, membership, and charm knowledge. A pantry-only dirty flag would be incorrect.
- Build memory indexes for only the targets queried within a read-only proposal pass, and reuse structural checks within a Pair. Invalidate on memory insertion, fading/softening, relationship updates, and defenses; do not reuse across mutable social interactions.
- Continue removing inventory enumeration/allocation in the projection, preserving ascending IDs and live deletion/hoisting semantics. Measure the built worker separately to distinguish TSX helper costs from production execution; no phone timing was measured here.

Behavior-changing options **not implemented**: shorter/approximate food projections, fewer ration/relief decisions, lower psyche cadence or candidate caps, fewer dialogue retries, and shorter listener retention. These can change thresholds, decisions, events, and RNG use and need design review.
