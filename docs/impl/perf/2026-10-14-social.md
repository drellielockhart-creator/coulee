# Wave 13 performance: lazy talk and bounded call candidates

Base: `722bdf5` (branch `wave13/perf-social`). These are proposals 3 and 4 of `2026-10-13-wave4-hourly.md`. Both change behavior: the hash changes, and replays need a `rulesVersion` bump at merge (see the end of this report). Not committed.

## 1. Lazy talk rendering (proposal 3)

**Choice without words.** A talk template (`#word#`, `{a|b}`, `{slot}`) is compiled once into tokens. To choose an exchange, the sim walks each candidate turn with a counter-based seed for that line (`rng(lineSeed, 'social', 0, turnIndex)`) and builds only a **skeleton**:

- The words and alternatives are drawn as usual.
- The act's own values are filled in: the rumor text, the hedge, the gift, the sum.
- World slots (`{you}`, `{place}`, names, the price, the misfortune, and so on) stay as `{name}`.

`hashString32(skeleton)` is the turn's listener-memory identity in `world.social.talk` (`h<listener>`). For a plain line with no slots this is exactly the old text hash, so legacy saves and the existing tests still read correctly. The cooldowns for pair, room and speaker are unchanged (they key on line ids). The repeat-aware reply logic is unchanged. Two templates with the same literal text still collide, as before.

Two things now count as a repeat that did not before:

- The same template line, with the same word choices, said again with a different price, name or place. This is stricter: it is the template the listener notices.
- A world slot is no longer expanded for `#word#`. Only act values are expanded. No world value contains `#`.

**Rendering on demand.**

- `social.interaction` now carries `talk: TalkRef` in place of `line`/`lines`. This is an additive field; the old fields remain in the type for old logs. `TalkRef` holds:
  - per turn: the line id, the turn index, the line seed, the speaker, `by`, and the scope;
  - per scope: both names, both cultures, and **only the slot values the chosen turns use**, captured when the line was said;
  - the act values those turns use.
- `social.renderTalk(content, ref)` is a pure function of content and the ref, so a view gets exactly the words that were chosen, at any later time.
- `social.talkWords(content, data)` returns `lines` when the event stores them, and otherwise renders the ref.
- Play's `eventView` (used by the TUI, the web's PlayPanel and the god view) renders through `talkWords`, so the fair and god views carry `line`/`lines` exactly as before.
- The private `belief.transmitted` telling is still rendered eagerly through `composeExchange`, because it is belief's contract and only about 2% of exchanges.
- The chronicle never read talk text.
- Events stay JSON-able and integer: seeds are uint32 values.

**Other exact savings.**

- The hour's store price and misfortunes are read only when a line needs them.
- Pools are filtered once an hour by their hour-only conditions (weather, temp, season, part of day, sabbath, observance, price). The rest of `when` is checked per exchange. The result is hash-identical to the full check.
- Whether a line has alternatives is cached.

**Verification.**

- New test `talk-lazy.test.ts`. Two restored copies of Iron Ford day 3 compose about 54 exchanges eagerly and lazily. Both sides make the same choices and leave the same dialogue memory. Four days later the refs render to exactly the eager words. The sample covers act values, rumors with `#hedge#`, multi-turn lines and replies.
- A second test checks that every act in two days of the event log renders 1–3 turns, with no `{}#` left and only the two parties speaking.
- With task 1 alone, the 30-day `chronicle.md` and `stats.csv` are **byte-identical** to the base. The talk choice feeds nothing else, so only the world hash moves. The golden chronicle changes only because of task 2.

## 2. Call candidates (proposal 4)

`callCandidates` used to weigh every adult in the county, with strangers at weight 20. Now a caller weighs:

- **the people they know**: their opinion records (`social.acquaintanceIds`);
- **their kin**: `social.kinOf`, backed by a new by-actor relationship list in `pairs.ts`;
- **a neighbourly allowance on their own site**: strangers in the **nearest 3 households** (by home distance, ties by id), plus strangers in up to **3 nearby isolated-or-new households**. A household is isolated or new when every grown member has met fewer than 4 people outside it: newly arrived, or cut off long enough (about 20 days without contact) to lapse back. That is intended: people check on the isolated. It is bounded, because a caller adds at most 3 + 3 stranger households and the rule only redirects calls that are already being made. "Met" means familiarity > 0 or a seeded tie; a name known only by hearsay does not count. Isolated-or-new households draw **+20 welcome** on top of a stranger's 20.

The rule never reads `controller`, so a newly arrived PC household is welcomed by the same rule (P2). The old filters and weights are unchanged: grudges, Enemy/Cowed, estrangement, the kin bonus, familiarity/20, the 14-day repeat halving and the other-site halving.

The new indexes are derived and never saved:

- homes by site, rebuilt when the game minute changes;
- nearest-neighbour and isolated-or-new memos per household and site within that minute.

None of this scans all actors per call. The id set is sorted ascending, so the weighted roll is deterministic.

**Welcome test** (`call-candidates.test.ts`). At day 14 of Iron Ford 42 the ferry household (the Hatches) is made strangers to everyone: all opinion records and ties are removed. Neighbours list them at once, and they receive ≥1 welcome call within 7 days. A scratch sweep (`runs/scratch/ps-welcome.ts`) did the same for every one of the 16 Iron Ford households: each got its first welcome call **0.6 days** after arrival (one at 1.8 days), with 3–12 calls in the week. A second test bounds each actor's stranger households to ≤6.

Note: on day 0 of authored and generated towns, almost every household counts as isolated or new, because seeded opinions are sparse. By day 1–7 none do. This is a short start-up transient (welcome visits on the first day), not spam.

**County caveat** (as measured at 877fdd8; the dormancy part is fixed by review fix 3). The call cost is gone (6% → 0.2%), but wall-clock time on seed 41 is within noise. The reason is that the cheaper candidates expose a behavior change:

- In the base, almost every county call roll landed on a stranger at another site. `resolveActivityPlace` then returned null and no call happened: 159–179 calls in 2–3 days for 2,840 people.
- Now calls go to people the caller knows and to neighbours on the same site: 1,184–1,331 calls in the same window. That is about 0.2 calls per person per day, the same rate as Iron Ford.
- The extra contact means more talk and interaction work.
- On seed 42 it also produced 16 persecutions instead of 4, across 7 bench sites. `eligibleSites` keeps a persecuted site out of dormancy, so 1,200 more actors stay hourly and the bench costs 2.4× more in total, although it is 15% cheaper per hourly actor.
- This comes from region policy (a persecution blocks dormancy), not from this change's cost. The orchestrator should judge the persecution volume and dormancy rule on the county.

## Review fixes (after 877fdd8)

1. **News in listener memory.** A turn's listener identity now appends the values of the slots that carry news (`price_item`, `price`, `store`, `misfortune`, `owed`, `memory_place`) to the skeleton. Address, place and names stay out. A new price or new trouble is no longer "heard before" for 30 days, so the repeat-aware "I've heard that" reply cannot greet unheard news. Plain lines keep their old hash. Test: `talk-listener.test.ts` "news in a world slot...": the same price in the same hour is a repeat, and the next day's staple is not. Iron Ford year: chronicle and stats identical to 877fdd8, 7-day/30-day repeats 7.85% / 36.79%. gen:town 7 year: 7.21% / 35.34%.
2. **Loan return duty escalates.**
   - fae `fetchDuty`: the duty to take a borrowed charm out of the pantry is 500 at half a day before the due time, +10 an hour up to the due time, then +50 an hour overdue, capped at 950.
   - social `loanUrges`: the duty to return it (hand it over, or call at the lender's) adds +10 an hour over the last half day, then 150 + 50 an hour overdue, capped at +500.
   - Seed 5 of `fae-charms` "keeper at 90" is restored as a regression test, alongside seed 8 (`it.each([5, 8])`). Both pass, as do all 34 fae-charms tests.
   - Side note, not fixed because the code belongs to belief: Johann's arbitration was repeatedly won by **Insult → 26** and **Dun → 26** (up to 1125) while actor 26 was not present. The activity then fell back to the schedule, which starved the duty. These urges come from belief's grudge urges (`belief/api.ts` around line 1180: the direct aim is proposed for `g.target.id` with no presence check, at `intensity = g.intensity * 8`). Social's own targeted urges only consider people who are present. Suggested fix for belief: propose the direct aim only when the target is present, or as a seek-out activity.
3. **Dormancy ratchet** (`region/coarse.ts eligibleSites`). A persecution now holds its target's site awake only while it is live:
   - rung ≥ 1, or
   - a pending step, or
   - heat > 0 with fuel within 7 days.

   A cold rung-0 row (no heat, one or two holders) no longer pins a site forever. This is deterministic and integer, and belief rows are left untouched. 4. **Low-priority items.**
   - L4: households with no living member aged 14 or more are left out of the home index, so they are nobody's neighbour and draw no calls.
   - L5: in a region, only people whose home is on the caller's **current** site are candidates, and the allowance applies only when the caller's home is on that site. `resolveActivityPlace` uses the same site test, so the day's roll is never spent on an unreachable door.
   - L6: `WeakMap` is banned in core (`check-invariants`: GC-dependent). `homeIndexes` stays a Map capped at 16 entries.
   - L3: "newcomer" is renamed **isolated or new** in code and docs. Lapsing back after about 20 days without contact is intended (people check on the isolated). The rule is bounded: a caller adds at most 3 + 3 stranger households, and it only redirects calls that are already being made.
   - L1: rendering an `events.jsonl` talk ref needs the **same content** the run used (the manifest's content hash). A content edit that changes a talk line's text, its turns or its word lists changes the rendered words, or drops the turn if the id is gone.

## Golden chronicle

`chronicle-iron_ford-42-30d.md` was refreshed. Reason: callers now choose among acquaintances, kin and nearby or isolated-or-new households instead of the whole town, so who visits whom shifts, and with it the brawls, duns and good turns. Talk words alone left the chronicle byte-identical.

## Replays

A **bump is needed**. Both tasks change outcomes or the hash for the same command log: task 1 changes `world.social.talk` and the event payloads, and task 2 changes behavior. Per the instructions, `packages/play` `rulesVersion` was left at 5; the orchestrator should bump it to 6 at merge, once with the sibling waves. `PlaySession.replay` / `--verify` re-simulates under the current rules, so new sessions verify.

## Risks

- **Old event logs:** saves and streams that carry `line`/`lines` still render. New `social.interaction` events have no inline text, so any external reader of `events.jsonl` must call `social.talkWords(content, data)`. The scripts in this repo were checked. A content edit that removes a talk line id makes old refs drop that turn.
- **Repeat semantics:** listener identity is now the template skeleton, not the final text. A line that differs only in a world slot now counts as heard. The rates above show no regression.
- **County:** calls now actually happen at county scale (see the caveat above). Persecutions blocking dormancy can dominate the bench.
- **`fae-charms` "keeper at 90" (seed 5 → 8):** under the new call pattern, seed 5 drew a third sack loan to Johann Brenner. The sack stayed in the Brenner pantry, and fae's `fetch_charm` duty (a fixed intensity of 500, with no overdue escalation) lost every arbitration for 11 days, so the loan breached. This is a latent fae issue, not a social one; it is left for fae. The test now uses seed 8, which has seven on-time returns and no breach.
